ZEMEN TECHNOLOGIES 01 / 06 • RELEASES

Semantic Versioning (SemVer) & Git Tags

Standard version structure: MAJOR.MINOR.PATCH (e.g., v2.4.1)

MAJOR (v2.0.0)

Breaking API or schema changes. Incompatible with previous versions.

MINOR (v1.5.0)

New backward-compatible functionality or endpoint additions.

PATCH (v1.4.2)

Backward-compatible bug fixes or security patches.

# Create an annotated release tag (ALWAYS use -a for releases)
git tag -a v2.4.0 -m "Release v2.4.0: Add CBE Birr webhook handler"

# Push tag to trigger production deployment pipeline
git push origin v2.4.0
ZEMEN TECHNOLOGIES 02 / 06 • GITOPS

GitOps: Git as the Single Source of Truth

No engineer SSHs into production to run kubectl apply or docker run.

All infrastructure state is declared in version-controlled repositories.

  • Auditable: Every configuration change has a commit author and PR review.
  • Reproducible: Spin up identical staging clusters in minutes.
  • Zero-Downtime Rollback: Simply run git revert to roll back bad infrastructure!

GitOps Controller Loop

1. Engineer merges PR into main
2. Tag v2.4.0 pushed
3. CI builds & pushes Docker image
4. GitOps agent detects new manifest
5. Kubernetes syncs live cluster state
ZEMEN TECHNOLOGIES 03 / 06 • SECURITY

Zero Secrets in Git: The Golden Rule

CRITICAL: Never commit AWS keys, database passwords, JWT secrets, or payment credentials into Git—even in private repositories!

Automated Pre-commit Scanning:

Install Gitleaks to intercept credentials before they leave your workstation:

# Install Gitleaks pre-commit hook
gitleaks protect --staged -v

What if a secret was committed?

Deleting the commit is NOT enough. The secret is compromised.

  1. Immediately rotate / revoke the API key on the service provider.
  2. Purge git history using git-filter-repo.
ZEMEN TECHNOLOGIES 04 / 06 • DATABASE MIGRATIONS

Handling Database Migrations in Git

When multiple engineers write Prisma/TypeORM/Flyway migrations simultaneously:

Timestamp Collisions

Two branches generate migration files with timestamps out of order.

Can cause production migrations to execute out-of-order and crash.

The Zemen Protocol:

Before merging any migration PR, rebase against latest main and run: 

git fetch origin
git rebase origin/main
npm run test:migrations

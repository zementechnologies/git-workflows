ENGINEERING PLAYBOOK 01 / 05 // RELEASES

Semantic Versioning (SemVer) & Tags

MAJOR (v2.0.0)

Breaking API or schema changes. Incompatible with previous versions.

MINOR (v1.5.0)

Backward-compatible functional additions or new endpoints.

PATCH (v1.4.2)

Backward-compatible bug fixes or security patches.

# Create annotated release tag (ALWAYS use -a for releases)
git tag -a v2.4.0 -m "Release v2.4.0: Add CBE Birr webhook handler"

# Push tag to trigger production deployment pipeline
git push origin v2.4.0
ENGINEERING PLAYBOOK 02 / 05 // GITOPS

GitOps: Declarative Infrastructure

No engineer applies production infrastructure changes manually over SSH. All desired state is declared in version-controlled repositories.

  • Auditable: Every configuration change has a commit author and PR review.
  • Reproducible: Staging and production clusters are synchronized from Git.
  • Rollback: Inverting a bad release requires only a git revert.

Reconciliation Pipeline

1. Pull Request merged to main
2. Tag v2.4.0 created
3. CI builds & verifies container image
4. GitOps agent reconciles manifest
5. Production deployment synchronized
ENGINEERING PLAYBOOK 03 / 05 // SECURITY

Zero Credentials in Git History

Mandate: Never commit API keys, database credentials, JWT secrets, or private certificates into Git repositories.

Pre-commit Secret Scanning:

# Install Gitleaks pre-commit check
gitleaks protect --staged -v

Remediation if Secret is Committed:

  1. Immediately revoke and rotate the credential with the provider.
  2. Purge repository history using git-filter-repo.

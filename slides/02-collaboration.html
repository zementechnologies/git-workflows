ZEMEN TECHNOLOGIES 01 / 06 • STRATEGY COMPARISON

Branching Models: Which to Use?

1. GitHub Flow

Zemen Standard for Web & SaaS: Short-lived feature branches cut from main, tested, PR reviewed, and merged directly to deploy.

Fast, continuous delivery

2. Trunk-Based

Developers merge tiny commits to main multiple times per day behind feature flags. Requires robust automated CI test suites.

Ideal for high-velocity teams

3. GitFlow

Complex branches: develop, release/*, hotfix/*, main. Heavy overhead. Only for scheduled versioned releases.

Avoid for cloud services
ZEMEN TECHNOLOGIES 02 / 06 • CONVENTIONS

Zemen Branch Naming Standards

Branch names must be descriptive and follow the pattern <type>/<ticket-id>-<short-desc>:

  • feat/ New feature or user capability
  • fix/ Bug fix for an issue
  • perf/ Performance optimization
  • refactor/ Code cleanup without behavior change
  • chore/ Tooling, dependencies, config updates
# Recommended examples:
git switch -c feat/ZM-204-payment-gateway
git switch -c fix/session-timeout-redirect
git switch -c refactor/cms-article-parser
git switch -c chore/upgrade-nextjs-15

# Bad branch names:
# x fix
# x aaron-patch
# x updates-new
ZEMEN TECHNOLOGIES 03 / 06 • COMMIT QUALITY

Conventional Commits Standard

Structure your commits so automated changelogs and version bumps work seamlessly:

<type>(<optional-scope>): <imperative short description>

[optional detailed body explaining WHY, not WHAT]

[optional footer: Closes #123, BREAKING CHANGE: ...]
Good Commit Message:
feat(auth): add OAuth2 refresh token rotation
Prevents token replay attacks by issuing a single-use refresh token on every renewal request.
Bad Commit Message:
fixed stuff
Provides zero context for reviewers or future engineers running git bisect.
ZEMEN TECHNOLOGIES 04 / 06 • PULL REQUESTS

The Anatomy of a 5-Star Pull Request

What reviewers want to see:

  1. Context & Motivation: Why is this change needed? Link ticket / issue.
  2. Visual Proof: Screenshots or Loom recording for UI changes.
  3. Verification Steps: Step-by-step instructions to test locally.
  4. Small Scope: Less than 400 lines changed per PR whenever possible.
Zemen Golden Rule: The easier a PR is to review, the faster it gets merged into production!

ZEMEN TECHNOLOGIES 05 / 06 • MERGE STRATEGIES

Squash vs Rebase vs Merge Commit

Squash and Merge

Collapses all WIP branch commits into 1 clean commit on main.

Zemen Default for Features

Rebase and Merge

Replays each individual commit onto the tip of main. Keeps linear history.

Good for curated series

Create a Merge Commit

Creates a 2-parent merge node preserving exact branch timeline.

Used for release branches

ENGINEERING PLAYBOOK 01 / 06 // MODELS

Branching Models Compared

1. GitHub Flow

Zemen Default: Short-lived feature branches cut from main, verified via CI, peer-reviewed, and squash-merged to deploy.

Standard for SaaS & APIs

2. Trunk-Based

Developers merge small changes directly to main multiple times daily behind feature flags. Requires extensive automated test suites.

High-frequency delivery

3. GitFlow

Multiple long-lived branches (develop, release, hotfix, main). High merge overhead.

Avoid for cloud services
ENGINEERING PLAYBOOK 02 / 06 // TAXONOMY

Zemen Branch Taxonomy

All branches must follow: <type>/<ticket-id>-<short-desc>

  • feat/ New user feature or API endpoint
  • fix/ Defect correction for an existing feature
  • perf/ Performance optimization
  • refactor/ Internal restructuring without behavioral change
  • chore/ Tooling, dependency, or configuration updates
# Valid branch names:
git switch -c feat/ZM-204-payment-gateway
git switch -c fix/session-timeout-redirect
git switch -c refactor/cms-parser
git switch -c chore/upgrade-nextjs-15

# Invalid branch names:
# x fix
# x patch-1
# x updates-new
ENGINEERING PLAYBOOK 03 / 06 // COMMITS

Conventional Commits Specification

<type>(<optional-scope>): <imperative short description>

[optional detailed body explaining WHY, not WHAT]

[optional footer: Closes #123, BREAKING CHANGE: ...]
Compliant Commit Message:
feat(auth): add refresh token rotation
Prevents replay attacks by issuing single-use refresh tokens on each renewal.
Non-Compliant Commit Message:
fixed bugs and stuff
Provides zero context for bisect audits or automated release notes.
ENGINEERING PLAYBOOK 04 / 06 // REVIEWS

Pull Request Review Criteria

Required in Every PR:

  1. Context & Problem: Why is this change necessary? Link the issue.
  2. Verification Steps: Explicit commands or steps to test locally.
  3. Visual Evidence: Screenshots or console output for UI changes.
  4. Constrained Scope: Keep diffs under 400 lines wherever practical.
## Description
Implements telebirr checkout callback verification.

## Testing Steps
1. Run `npm run dev`
2. Navigate to `/checkout/test`
3. Verify successful redirect to `/receipt`

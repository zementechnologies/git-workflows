Foundational Curriculum

Git From Scratch: Zero to First Pull Request

An approachable, comprehensive guide for beginners. Understand what version control is, how Git differs from GitHub, the four file states, and how to submit your first contribution with confidence.

Duration: 45 min Target: Absolute Beginners, Junior Devs, Interns Prerequisites: None
ENGINEERING PLAYBOOK 01 / 15 // WHY GIT

The Chaos of Coding Without Version Control

The Old Folder Nightmare

Before version control, people saved copies like this:

project_v1/
project_v2_final/
project_v2_final_FINAL/
project_v2_final_FINAL_aaron_edit.zip

No one knows who changed what line, why a change was made, or how to undo an error without breaking everything.

What Git Provides

  • Time Machine: Travel to any point in the history of your codebase.
  • Attribution: Know exactly who wrote every line, when, and why.
  • Parallel Universes: Experiment in isolated branches without breaking production.
  • Safe Merging: Combine work from 50 engineers into one unified project.
ENGINEERING PLAYBOOK 02 / 15 // CONCEPTS

Git vs GitHub: The Crucial Difference

Git (The Tool)

A command-line software program running locally on your computer.

  • Runs completely offline without an internet connection.
  • Tracks file snapshots, branches, and commit histories on your local disk.
  • Created by Linus Torvalds in 2005. Free and open source.

GitHub (The Cloud Platform)

A cloud hosting service and web application for Git repositories.

  • Hosts remote copies of your repositories in the cloud.
  • Provides web UI for Pull Requests, Code Reviews, and Issue Tracking.
  • Runs automated testing (CI/CD) and team permission management.
ENGINEERING PLAYBOOK 03 / 15 // LIFECYCLE

The Four States of Any File in Git

At any given second, every file in your folder is in one of these four states:

1. Untracked

A brand new file you created that Git has never seen before. Git will not record it until you tell it to track it.

2. Modified

A file Git already tracks that you edited in VSCode. You have changes on disk that are not yet staged.

3. Staged

You ran git add. The file is packaged and ready to be sealed into the next snapshot commit.

4. Committed

You ran git commit. The snapshot is safely and permanently stored in your local Git database.

ENGINEERING PLAYBOOK 04 / 15 // CONFIG

One-Time Setup on Your Machine

Tell Git who you are so your commits attribute to your Zemen profile:

# Set your display name (used in commit author logs)
git config --global user.name "Your Full Name"

# Set your corporate email address
git config --global user.email "yourname@zemen.com.et"

# Set the modern default branch name to 'main'
git config --global init.defaultBranch main

# Set your default text editor to VSCode
git config --global core.editor "code --wait"

# Verify your configuration
git config --list
ENGINEERING PLAYBOOK 05 / 15 // STARTING

How to Start: git init vs git clone

Option A: Brand New Project (git init)

When starting a brand new application from an empty folder on your computer: 

mkdir my-new-project
cd my-new-project
git init
# Creates hidden .git folder

Option B: Existing Team Project (git clone)

When joining an existing project already hosted on Zemen Technologies GitHub: 

git clone https://github.com/zementechnologies/git-workflows.git
cd git-workflows
# Copies full project & history
ENGINEERING PLAYBOOK 06 / 15 // STATUS

The First Command You Should Always Run: git status

Never type commands blindly. git status tells you what branch you are on and what has changed: 

$ git status
On branch main
Changes not staged for commit:
  (use "git add <file>..." to update what will be committed)
  modified:   src/app/page.tsx

Untracked files:
  (use "git add <file>..." to include in what will be committed)
  src/components/Header.tsx

# Quick pro-tip: use compact status
$ git status -s
 M src/app/page.tsx
?? src/components/Header.tsx
Tip: ?? means untracked file, M means modified file.
ENGINEERING PLAYBOOK 07 / 15 // STAGING

Staging Changes: Packing Your Suitcase

Think of a commit as sending a package in the mail. Staging (git add) is putting specific items into the box before sealing it. 

# Stage a single specific file (RECOMMENDED)
git add src/components/Header.tsx

# Stage multiple related files
git add src/app/page.tsx src/styles/main.css

# Stage individual chunks of a file interactively (BEST PRACTICE)
git add -p src/components/Navbar.tsx

# Unstage a file if you added it by accident
git restore --staged src/secret.env
Caution for beginners: Avoid running git add . blindly without checking git status first. You might accidentally stage sensitive files or build folders.
ENGINEERING PLAYBOOK 08 / 15 // COMMITTING

Making a Commit: Sealing the Box

A commit permanently saves your staged files as a new checkpoint in history: 

# Create commit with an imperative message
git commit -m "feat(auth): add login form validation"

# Output from Git:
[feat/login 4f82c19] feat(auth): add login form validation
 2 files changed, 48 insertions(+), 3 deletions(-)

What a Commit Contains:

  • A unique 40-character SHA-1 hash (e.g. 4f82c19...)
  • Your name and email as author
  • Exact date and time stamp
  • Reference to the previous commit (parent)

Golden Rule:

Make commits atomic: one logical task per commit. Do not combine database migrations, UI changes, and CSS fixes into a single commit!

ENGINEERING PLAYBOOK 09 / 15 // MESSAGES

Writing Messages Future You Will Thank You For

Bad Commit Messages (Avoid!):

git commit -m "updates"
git commit -m "fixed stuff"
git commit -m "asdf"
git commit -m "trying again"
git commit -m "final test"

Gives zero clues when a bug appears 3 months later.

Good Conventional Messages:

git commit -m "feat(cart): calculate VAT for Ethiopian Birr"
git commit -m "fix(nav): prevent drawer closing on scroll"
git commit -m "docs(readme): add local postgres instructions"
git commit -m "refactor(api): extract payment client into service"

Clear prefix, clear scope, explains exact intent.

ENGINEERING PLAYBOOK 10 / 15 // BRANCHES

What is a Branch and Why You Must Use Them

Never commit directly to main. Always work inside your own branch!

Think of a branch as your private sandbox. If your experiment completely fails, you can delete it without hurting anyone else's code. 

# 1. Create and switch to your feature branch
git switch -c feat/telebirr-qr-code

# 2. Check which branch you are on
git branch
# Output:
# * feat/telebirr-qr-code
#   main

# 3. Switch back to main when needed
git switch main
ENGINEERING PLAYBOOK 11 / 15 // REMOTES

Working with GitHub: origin, push & pull

What is origin?

origin is simply a nickname Git gives to the remote repository on GitHub where you cloned your code. 

# Check your remote URL
git remote -v
# origin https://github.com/zementechnologies/...

Pushing & Pulling:

# Push your new branch to GitHub for the first time
git push -u origin feat/telebirr-qr-code

# On subsequent pushes:
git push

# Download latest team updates from main:
git switch main
git pull origin main
ENGINEERING PLAYBOOK 12 / 15 // PULL REQUESTS

What is a Pull Request (PR)?

A Pull Request is a formal proposal: "Hey team, I finished this feature in my branch. Please review my code before we merge it into main."

  1. Push your branch to GitHub.
  2. Click "Compare & pull request" on GitHub.
  3. Write a clear summary of what you did.
  4. Automated CI tests verify that your code compiles.
  5. A teammate approves your code & merges it!

Anatomy of a Great PR:

## What Changed
Added CBE Birr QR code generator component.

## How to Test
1. Go to `/checkout`
2. Select "CBE Birr"
3. Scan QR code and verify payment confirmation screen.
ENGINEERING PLAYBOOK 13 / 15 // CONFLICTS

Merge Conflicts: Do Not Panic!

A merge conflict only happens when you and another developer edit the exact same lines of the same file. Git stops and asks: Which version do you want? 

<<<<<<< HEAD (Current version on main)
const taxRate = 0.15; // 15% VAT
=======
const taxRate = 0.18; // New VAT rate from finance
>>>>>>> feat/update-tax (Your version)
How to resolve it:
  1. Open the file in VSCode.
  2. Delete the markers (<<<<<<<, =======, >>>>>>>).
  3. Keep the correct code.
  4. Run git add <file> && git commit. Done!
VSCode Helper:
VSCode provides buttons above the conflict: "Accept Current Change", "Accept Incoming Change", or "Accept Both".
ENGINEERING PLAYBOOK 14 / 15 // STASHING

The Safety Drawer: git stash

Scenario: You are halfway through coding a feature, and your manager asks you to urgently fix an emergency bug on main. 

# 1. Stash your unfinished work into a safe drawer:
git stash push -m "WIP: halfway through payment UI"

# 2. Your workspace is now 100% clean! Switch to main and fix bug:
git switch main
# fix bug, commit, push

# 3. Switch back to your feature branch and pull your work back out:
git switch feat/my-feature
git stash pop
# All your uncommitted edits are restored exactly as you left them!
ENGINEERING PLAYBOOK 15 / 15 // GLOSSARY

Beginner Cheat-Sheet Glossary

  • Repository (Repo): The folder containing your project and all its Git history.
  • Commit: A permanent snapshot of your project with a message and timestamp.
  • Branch: A lightweight pointer to work independently on a feature.
  • HEAD: Pointer representing what you currently have open on your screen.
  • Remote (origin): The cloud copy of the repository hosted on GitHub.
  • Pull Request (PR): A proposal to merge your branch into main.
  • Diff: The exact lines added (green) or removed (red).
  • Stash: A temporary drawer to hold uncommitted changes.

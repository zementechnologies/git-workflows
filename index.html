03 / EMERGENCY RUNBOOK

Common Scenarios & Commands

Copy command with one click
Scenario Remediation Command
Typo in Last Commit Message
Correct the commit message before pushing to remote.
git commit --amend -m "feat(scope): revised message"
Committed Directly to Main Branch
Move unpushed commits from main into a new feature branch.
git branch feat/my-work && git reset --hard origin/main
Accidental Hard Reset (Lost Commits)
Find the lost commit hash in the reflog and restore to a branch.
git reflog && git checkout -b rescue-branch <commit-hash>
Package Lockfile Merge Conflict
Accept incoming package.json and regenerate cleanly.
git checkout --theirs package.json && npm install
Undo a Pushed Commit on Shared Branch
Revert the changes forward without rewriting history.
git revert <commit-hash> && git push origin main
Squash Last 3 Local WIP Commits
Interactive rebase to clean up history prior to opening a PR.
git rebase -i HEAD~3
04 / GOVERNANCE

Zemen Engineering Standards

Repository rules of engagement

Branch & Commit Hygiene

Clean history is an operational prerequisite. Linear commit histories allow rapid regression tracking and safe rollbacks during production incidents.

  • 01. All branches cut from and target the main branch directly.
  • 02. Commit messages must follow Conventional Commits (type(scope): description).
  • 03. Commits must be atomic: one logical change per commit.
  • 04. Never force push to shared branches (main, staging).

Review & Release Standards

Code review is a core quality filter. Every pull request requires automated verification and human consensus prior to merge.

  • 05. Pull requests require at least one approving peer review.
  • 06. Continuous integration tests, linter checks, and builds must pass green.
  • 07. Features are merged via Squash and Merge to keep main linear.
  • 08. Production deployments are triggered strictly by annotated Git tags.
